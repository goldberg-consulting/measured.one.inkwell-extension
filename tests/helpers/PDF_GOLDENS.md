# PDF raster goldens

The harness reads existing PDFs. It never compiles source or silently creates a baseline. Python needs Pillow and PyMuPDF; rendering uses the bundled `pdftoppm` when available. Installed TeX package/font inputs must remain available.

Prepare a JSON array of `{ "id": "demo-default", "template": "default", "pdfPath": "/absolute/demo-default.pdf", "logPath": "/absolute/attempt/compile.log" }`. Optional `flsPath` and `engineLogPath` identify the actual TeX recorder and engine log; otherwise they are siblings of `logPath`, using the PDF's basename. Optional `fontFiles` disambiguates exact source font binaries when multiple installed fonts share a PostScript name.

Run the check with:

```sh
python3 scripts/check-raster-goldens.py \
  --manifest /private/tmp/inkwell-raster-demos.json \
  --goldens tests/goldens \
  --output /private/tmp/inkwell-raster-review \
  --artifact-sha256 ACTUAL_64_CHARACTER_VSIX_SHA256 \
  --extension-root /absolute/verified-unpacked/extension
```

`--pdftoppm` and `--pandoc` select exact tools. Their versions and hashes, the engine version from the actual TeX log, installed TeX package sources, recorded font inputs, selected full font binaries, OS/architecture, and rendering settings are pinned in each baseline. Missing platforms, tools, font identities, input files, or baseline metadata fail. Selected font binaries are matched against the PDF's PostScript font names using OpenType/Type1 metadata, because XeTeX's recorder does not include OS main fonts. Font subsets extracted from the PDF are deliberately not used as source-font hashes.

Repeat `--font-dir` (or set the path-separated `INKWELL_PDF_FONT_DIRS`) for the actual TeX installation's `texmf-dist/fonts/opentype` and the plotting interpreter's `matplotlib/mpl-data/fonts` directory when needed. These directories supply source font binaries omitted by the TeX recorder; unknown or ambiguous fonts still fail.

`--extension-root` recovers a deleted immutable template support cache only when its recorded cache fingerprint matches the supplied artifact's verified support-file inventory. Missing installed package or font inputs cannot be ignored. Bundled/custom `.sty`, `.cls`, and generated `.tex` are recorded separately as product inputs, so a product style change produces a rendered difference rather than being mislabeled as a changed toolchain.

The renderer produces RGB pages at 120 DPI. A pixel is changed if **any** RGB channel differs by **more than 10/255**. Each page passes when changed pixels are **at most 0.5%**; exactly 0.5% passes. Page-count or page-dimension changes fail. The report includes full-size before/after/difference PNGs and three-panel contact sheets for review.

To intentionally record or replace a baseline, add **both** `--record --allow-baseline-write`. This writes the baseline and preserves before/after/difference review artifacts. A successful recording has `requiresVisualReview: true`; it is not a visual approval. Review every changed page before accepting the baseline. The normal check never updates it.

Existing typography, table, and reference PDF tests accept:

- `INKWELL_PDF_ASSET_ROOT`: verified unpacked VSIX root; selects its bundled `smoke-cli.js` compiler facade.
- `INKWELL_PDF_GOLDENS=check`: require existing raster baselines after each real PDF.
- `INKWELL_PDF_ARTIFACT_SHA256`: required actual VSIX hash for the report.
- `INKWELL_PDF_GOLDENS_DIR` and `INKWELL_PDF_GOLDENS_OUTPUT`: optional baseline/review locations.
- `INKWELL_PDF_GOLDENS=record` plus `INKWELL_PDF_GOLDENS_ALLOW_RECORD=1`: explicit recording.
- `INKWELL_PDF_PYTHON`, `INKWELL_PDFTOPPM`, `INKWELL_PANDOC_BIN`: exact existing tool paths.

Run the pure comparison regressions with `python3 -m unittest discover -s tests -p 'test_raster_goldens.py'`. No checked-in baseline is generated by those tests.
