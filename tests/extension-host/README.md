# Packaged extension host gate

Run `node scripts/check-extension-host.cjs --vsix /absolute/path/inkwell-0.5.0.vsix --report /private/tmp/inkwell-host-report.json` on a Mac with Cursor installed. `--editor` can select an installed Code-compatible Electron application binary. No editor download or normal-profile extension installation occurs.

The script verifies the VSIX asset contract, extracts its exact bytes into a new temporary directory, and launches six fresh editor instances: one warmup and five measured samples. Each receives its own empty profile, extensions directory, and workspace. On macOS, executable builtin extensions are explicitly disabled in this test instance to reduce Cursor agent/Git startup activity; their IDs are recorded in the report, and language grammar contributions remain available. Cursor force-enables some builtins, so the host is given a fixed 1,000 ms to settle before measurement. The test asserts Inkwell is still inactive and its entrypoint is absent from the module cache, then explicitly activates it before opening any Markdown document. The report records the artifact hash, machine and editor runtime, corpus/test hashes, individual samples, median, p95, and variance. Activation p95 must be below 200 ms. Child-process instrumentation begins before activation and continues for 300 ms after completion; extension-origin calls must be zero. Unrelated builtin calls are recorded separately. This measures cold extension activation in a settled host, not total editor startup latency.

The final iteration checks actual editor commands and CodeLens providers: run an anonymous shell fence, verify that its ID was saved before execution, extract it to a script, rerun with identical output, edit and save the script, run changed blocks, compile its current inserted output to PDF, and clear generated output while preserving authored files. The PDF must have a valid header/trailer and contain the edited generated artifact according to `pdftotext` (Poppler, or the executable selected by `INKWELL_PDFTOTEXT`). Alternatively set `INKWELL_PDF_PYTHON` to an existing Python interpreter with PyMuPDF or pypdf; the report records the extractor used. The output marker is assembled at runtime so displayed source code alone cannot satisfy the insertion check. Filesystem migration helpers are bundled from the checkout solely to create the fixture after the activation measurement. Extension code under test always comes from the verified package. Asset bytes are checked again after all host tests.

The full mode then opens a short document with two citations and verifies the real completion provider, an actual Inkwell webview tab, and authoritative Pandoc cache output. One warmup and five measured bursts each make eight real editor edits 25 ms apart. Transparent API facades forward to the actual webview and observe its `ready` event and accepted `updateContent` messages. Every sample must publish its final edit marker at the current document version; independent bibliography cache creation cannot satisfy this check. `async_hooks.before/after` records the synchronous duration of every extension-host callback during the edits and their awaited preview refresh; a separate 10 ms timer records event-loop lag. Those shared-host observations are retained for diagnosis, while the gate enforces current publication and zero child processes for unchanged citation completion. Release performance is decided separately from retained same-machine baseline and confirmation benchmark reports. The report distinguishes callback durations from timer-lag proxies and records citation-cache artifact counts/bytes, accepted publication counts/HTML bytes, completion counts, and editor versions. Accepted messages prove host publication, not browser painting. Pandoc is required for this full fixture; missing authoritative output fails the gate.

`--mode activation` establishes only the activation and command-registration gate for an earlier candidate. `--mode preview` runs activation and warm-preview checks while another authoring change is under development. Neither focused mode claims to pass the complete authoring/PDF workflow. Missing editors, timeouts, unsupported test-runner launches, absent required commands, and behavioral failures are errors, never skipped successes. Temporary profiles and editor logs are retained at the location recorded in the report for inspection. On macOS and Linux the harness samples the launched editor's descendant lineage every 200 ms, retaining each process's PID and creation time across detached process groups. It verifies those identities before signaling owned processes, and applies bounded TERM/KILL cleanup on normal exit, timeout, and interruption. Cleanup failures fail the gate. Windows cleanup is not implemented and is rejected explicitly.

This test covers the Node extension host, editor command registration, and authored run lifecycle. It does not replace webview browser tests, a clean-machine installer journey, UI accessibility review, or Intel/macOS coverage.
